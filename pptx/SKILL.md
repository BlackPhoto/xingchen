# PPT 创建、编辑和分析

## 概述

当用户要求创建、编辑、读取或整理演示文稿时使用本 skill。创建新演示文稿时支持三条交付路线：

- 排版 PPT（`.pptx`）：兼容 PowerPoint / Keynote / WPS，文字、图表、形状等对象可编辑；可选 AI 配图作为素材。`.pptx` 文件本质上是 ZIP 压缩包，包含 XML 文件和其他资源；`.ppt` 是旧版 PowerPoint 格式，需要先转换为 `.pptx`。
- 网页演示文件（`.html`，有外部图片时包含 `images/` 目录）：视觉表现力强，支持 WebGL 背景和入场动效；需浏览器查看和修改，且仅支持预设主题色。
- 图片 PPT（`.pptx`）：每页是一张 AI 生成的完整图片，视觉质量高但页面文字和图表不可编辑；不适合精确数据、表格、长中文或后续协作编辑。

**时间约束（40 分钟控制目标）**：开始读取任务文件、分析素材或进入制作时，必须记录真实开始时间 `T0`，并计算控制点 `T_review = T0 + 40 分钟`；完整规则见 `references/shared/timebox.md`。所有路线统一使用从 `T0` 起算的累计里程碑：10 分钟内完成规划，30 分钟内产出首个可打开版本，剩余时间完成最多两轮 QA 与交付。到达 `T_review` 后必须停止扩展范围并判断当前版本是否可交付：已有可交付版本则结束；尚无可交付版本则进入一次最多 10 分钟的救援阶段，只处理形成最小可交付版本所必需的 P0 问题。救援阶段结束后仍不可交付，才停止并汇报。未完成版本不得称为“最终版”。上下文压缩、任务续接和工具失败不得重置计时。

**如果新增内容与原PPT内容，在格式上有冲突（重叠，溢出），可微调原PPT元素的位置，但微调后，不要存在格式问题（重叠，溢出）**

## 启动前资源检查

启动本 skill 后，执行任何 PPT 创建、编辑或视觉 QA 步骤前，必须先完成 LibreOffice 检查。仅当已选择 SVG 创建路线或后续步骤明确需要 SVG 资源时，才继续执行 SVG template 检查；双语原生重排、普通原生编辑和只读分析跳过 SVG template 检查。

### LibreOffice 前置检查与安装

LibreOffice 是本 skill 将 PPT 转换为 PDF/图片并执行视觉 QA 的必需依赖。先根据当前操作系统检查 `soffice`：

**Windows（PowerShell）**：

```powershell
$soffice = Get-Command soffice.com, soffice.exe -ErrorAction SilentlyContinue | Select-Object -First 1
if (-not $soffice) {
    $candidates = @(
        "$env:ProgramFiles\LibreOffice\program\soffice.com",
        "$env:ProgramFiles\LibreOffice\program\soffice.exe",
        "${env:ProgramFiles(x86)}\LibreOffice\program\soffice.com",
        "${env:ProgramFiles(x86)}\LibreOffice\program\soffice.exe"
    )
    $soffice = $candidates | Where-Object { $_ -and (Test-Path -LiteralPath $_) } | Select-Object -First 1
}
if ($soffice) { & $soffice --version }
```

**macOS（zsh/bash）**：

```bash
SOFFICE_BIN="$(command -v soffice || true)"
if [ -z "$SOFFICE_BIN" ] && [ -x "/Applications/LibreOffice.app/Contents/MacOS/soffice" ]; then
  SOFFICE_BIN="/Applications/LibreOffice.app/Contents/MacOS/soffice"
fi
[ -n "$SOFFICE_BIN" ] && "$SOFFICE_BIN" --version
```

如果未找到 LibreOffice，必须先告知用户将安装系统软件并取得明确授权；不得静默安装。用户同意后执行与平台匹配的命令：

**Windows 安装命令**：

```powershell
winget install --id TheDocumentFoundation.LibreOffice --exact --accept-package-agreements --accept-source-agreements
```

**macOS 安装命令**：

```bash
brew install --cask libreoffice
```

安装完成后必须重新执行对应平台的检测命令，并确认 `--version` 成功，再继续 PPT 工作流。如果 Windows 没有 `winget`、macOS 没有 `brew`、安装被拒绝或安装后仍无法运行，**降级而非全停**：

- **仍可执行**：`detect_layout.py` 布局自动检测（基于 XML 坐标，不依赖 LibreOffice）、`: markitdown` 内容 QA、SVG 质量检查与后处理、PPTX 导出。
- **不可执行**：转 PDF 渲染图片目检（需 LibreOffice）。
- **降级动作**：正常完成内容规划、SVG 生成、导出 PPTX 和 `detect_layout.py` 布局检测；布局检测通过后，向用户说明"已完成布局自动检测（覆盖文字重叠/溢出/空白/字号层级），但未做渲染级视觉检查（LibreOffice 不可用）"，并提供 LibreOffice 官方手动安装方案；**不得宣称完整视觉 QA 已完成或已通过**。

### SVG template 资源检查（仅 SVG 路线）

仅当任务实际进入 SVG 路线时，在 LibreOffice 检查通过后检查当前 skill 目录下的 SVG template 资源状态：

1. 若存在 `svg-templates/` 目录：资源已就绪，按正常流程继续。
2. 若不存在 `svg-templates/` 目录但存在 `svg-templates.zip`：先在当前 skill 目录解压 `svg-templates.zip`，确认生成 `svg-templates/` 后删除 `svg-templates.zip`，再继续执行。
3. 若两者都不存在：停止 SVG 路线并告知用户 SVG template 资源缺失；不得因此阻塞不使用 SVG 的原生 PPT 路线。                            

## 需求澄清

### 快速通道

如果用户同时满足以下 4 项，跳过输出路线、大纲、风格、篇幅等其余澄清，直接进入路由执行；**生成模式（仅排版 PPT 路线）：若用户提供模板则直接走快速模式、不询问；若无模板则仍必须单独询问，不得跳过**：

1. 明确指定输出路线（排版 PPT、网页演示或图片 PPT）。
2. 提供完整大纲。
3. 提供模板或明确要求的风格。
4. 指定 ppt 篇幅和信息呈现偏好。

即使满足快速通道，只要交付形态为排版 PPT，若无模板则必须先询问用户选择快速模式还是质量模式，得到明确答复后才可执行；若用户提供了模板，直接走快速模式，不询问生成模式。如果不满足快速通道，必须进入最多两轮的澄清流程。

### 最多两轮澄清

#### 第一轮：只确认输出路线

仅当用户既没有明确输出路线，也没有提供模板/现有 PPT 时，第一轮只问一个问题（**任何情况下都必须向用户询问，禁止跳过或默认**）：

**注意**： 用户说“帮我做一个ppt/演示文档”，不算是指定生成`.pptx`格式

```markdown
你希望这次交付为哪种形式？

- **排版 PPT**（`.pptx`）：内容可自由修改，适合汇报、协作和后续完善。
- **网页演示**（`.html`，有图片时包含 `images/` 目录）：视觉效果丰富，支持交互，适合演示、展示和发布
- **图片 PPT**（`.pptx`）：页面效果稳定，适合直接展示，但内容无法编辑。
```

第一轮禁止同时询问视觉风格、主题色、受众、时长、素材或硬性约束。

如果用户已经明确输出路线，或已经提供模板/现有 PPT，则跳过第一轮：

- 明确说 `.pptx` / 可编辑的演示文稿 → 视为排版 PPT 路线。
- 明确说网页演示 / HTML  / 典雅画报风网页 PPT / 简约商务风网页 PPT → 视为网页路线。
- 明确说纯图 PPT / 图片 PPT / 每页一张图 → 视为图片 PPT 路线。
- 提供模板或现有 `.pptx` / `.ppt` 文件 → 视为排版 PPT 路线，不再询问输出格式。

若输出路线为排版 PPT，无论用户是否已在指令中写明模式，**生成模式都必须向用户询问并得到明确答复（没有模板的情况下）**。即使指令中已出现"质量模式""快速模式"字样，也必须再次向用户确认一次，避免误解；用户明确答复后才按所选模式执行。


#### 第二轮：一次性收集所有缺失项

输出路线明确后，第二轮一次性询问该路线下仍缺失的所有待确认项。用户已经明确说过或可稳定推断的信息不要重复问。

第二轮之后不得继续追问。若用户仍未回答完整，使用合理默认值继续，并在执行前的配置摘要中标注“未提供，按默认处理”。

### 第二轮确认项

如果 `#1 = 排版 PPT`：

- 视觉风格：商务简约、科技专业、正式庄重、温润亲和、高端品牌、中国风、自定义。
- 主题色：可根据既有 `.pptx` 设计体系推荐，也可接受用户指定色值或品牌色。
- 视觉素材来源：已有自备图片/图表/截图、需要 AI 生成、不需要图片。
- 生成模式（排版 PPT 路线必选，**只要没有提供模板都必须向用户询问，禁止跳过或默认，如果用户提供模板，直接走快速模式**）。以下为展示给用户的确认话术，**禁止出现「PptxGenJS」「ppt-slide」「html2pptx」「几何体检」「多模态」等内部技术词**，改用用户能直接理解的说法：

  ```markdown
  请选择这次 PPT 的制作方式（无模板时必选，若已提供模板则跳过此项，直接走快速模式）：

  ○ 快速模式
  生成速度更快，适合内容较简单、希望快速完成 PPT 的场景。

  ○ 质量模式
  页面设计更精细，内容和版式经过更充分的检查，适合汇报、方案等对 PPT 质量要求较高的场景。
  ```

  内部对应关系（仅执行参考，不告知用户）：
  - 快速模式 → 轻量引擎，排版为主、速度快、积分消耗少，全部内容原生可编辑。
  - 质量模式 → 精细引擎，视觉质量显著更高，支持复杂布局（中心辐射/环形循环/树形层次等）、多套配色主题自动匹配、逐页双重质检；大部分内容可编辑，少数复杂视觉元素可能转为图片。

如果 `#1 = 网页演示文件`：

- 视觉方案（风格与主题色已绑定，不接受单独指定主题色）：
  - **典雅画报风**：
    - 墨水经典（通用 / 商业发布 / 默认）
    - 靛蓝瓷（科技 / 研究 / 数据）
    - 森林墨（自然 / 可持续 / 文化）
    - 牛皮纸（怀旧 / 人文 / 文学）
    - 沙丘（艺术 / 设计 / 创意）
  - **简约商务风**：
    - 克莱因蓝（汇报 / 路演 / 科技 / 默认）
    - 柠檬黄（活力 / 消费 / 零售）
    - 柠檬绿（生态 / 新兴 / 未来）
    - 安全橙（工业 / 警示 / 运动）

如果 `#1 = 图片 PPT`：

- 每页主题：用户提供逐页描述，或只给一个大主题由 Agent 拆分。
- 图片风格：商务专业、杂志编辑、科技未来、极简海报、数据可视化。
- 页数：用户指定或由 Agent 根据时长推断；若生图服务返回额度限制，再请用户减少页数、分批生成或切换路线。
- 页面文字：由生图模型直接生成，文字和图表不可编辑；若内容包含精确数据、表格、KPI、长中文或品牌法务文本，必须建议切换到排版 PPT。

除此之外，三种路线均需要确认以下细节：

- 应用场景与受众：如部门例行汇报、领导班子专项汇报、技术分享/培训、商业提案/路演、年度/季度总结、行业观察/研究分享。
- 演示时长或页数：参考 5-10 分钟约 5-8 页，15 分钟约 10 页，30 分钟约 20 页，45 分钟约 25-30 页。
- 信息呈现偏好：文字叙述为主、图表可视化为主、图文并重、由 Agent 根据场景判断。
- 内容来源：已有原始素材、已有要点、只有主题需 Agent 组织大纲。
- AI 配图方案（排版 PPT / 网页演示适用，图片 PPT 跳过此项）（单选），请注意你必须在选项中向用户说明生图额度消耗的风险：
  - **不需要**：纯文字与原生组件
  - **精简配图**：1-2 张关键配图（推荐，大多数场景够用）
  - **精简 + 候选**：精简配图，关键主视觉生成多张候选选最佳（效果更好，额度消耗约翻倍）
  - **多配图**：所有适合放图的页面各 1 张 AI 配图（生图额度消耗较多）
  - **多配图 + 候选**：多配图 + 关键主视觉多张候选（额度消耗极大）
  - 若用户有自备图片/图表/截图，可在本项之外另行说明，与 AI 配图不互斥。
- 硬性约束：必须包含/不得出现的内容、保密要求、页数上限、特定结构、品牌规范等。

**网页视觉方案确认话术（硬约束）**：当用户已选择或已确定为网页演示文件（HTML 类 PPT），且视觉方案尚未确认时，必须按风格分组呈现所有可选方案，让用户一次性选定风格 + 主题色组合，避免风格与主题色错配。

向用户确认视觉方案时，优先使用下方标准话术（可按上下文微调措辞，但不得删掉分组结构和场景说明）：

```markdown
请选择网页演示的视觉方案（风格与主题色绑定）：

**典雅画报风**：大图 + 衬线标题，偏人文叙事。
- 墨水经典 — 通用 / 商业发布 / 不知道选啥的默认
- 靛蓝瓷 — 科技 / 研究 / 数据
- 森林墨 — 自然 / 可持续 / 文化
- 牛皮纸 — 怀旧 / 人文 / 文学
- 沙丘 — 艺术 / 设计 / 创意

**简约商务风**：版式规整、数字醒目，偏信息清晰。
- 克莱因蓝 — 汇报 / 路演 / 科技 / 不知道选啥的默认
- 柠檬黄 — 活力 / 消费 / 零售
```

### 澄清执行规则

1. 澄清最多两轮，严禁追加第三轮。
2. 第一轮只在输出路线无法从用户输入或模板/现有文件中推断时触发，且只能问输出路线。
3. 第二轮一次性提出所有缺失确认项；可以用多个问题块，但必须同轮发出。
4. 用户已提供或可基于上下文推断的信息不要重复询问。
5. 用户未回答的项目用合理默认值继续，并在配置摘要中标注默认值。**但生成模式（排版 PPT，无模板时）属于例外，不设默认值，必须在第二轮明确询问并等待用户答复；用户未答复前不得进入执行。若用户提供模板，生成模式直接默认为快速模式，无需询问。**
6. **网页路线 + 需确认视觉方案时**：必须按风格分组呈现所有可选方案（风格 + 主题色绑定组合），不得先列某一风格的全部主题色再让用户选风格；违反视为澄清不合格。

## 路由

### 创建排版 `.pptx`

适用：用户需要标准 PowerPoint 文件，或需要后续编辑、协作、套模板、兼容办公软件。

#### 引擎路由（内部执行，不告知用户）

- **快速模式** → PptxGenJS：直接生成可编辑 PPTX，全部内容原生可编辑
- **质量模式** → ppt-slide：HTML 逐页生成 → 几何体检 + 多模态视觉检查 → html2pptx 转换为可编辑 PPTX

> 快速模式下遇到桑基/瀑布/漏斗/旭日/弦/复杂雷达等图表时，告知用户「该图表将以可编辑方式近似实现，数值和文字均可编辑」。质量模式下这些图表可直接用 SVG 精确绘制。

不得向用户提及「PptxGenJS」「ppt-slide」「html2pptx」等技术词。

#### 入口 workflow

- **快速模式**：完整读取 `references/pptx/create-workflow.md`
- **质量模式**：完整读取 `references/ppt-slide/slide-workflow.md`

只读取入口 workflow，后续 reference 由各 workflow 按阶段和条件指引读取。

#### 双语专项条件路由（仅双语任务触发）

仅当用户明确要求“中英双语”“bilingual”“添加英文翻译”或等价目标时，才完整读取并执行 `references/pptx/bilingual-workflow.md`。普通单语 PPT 不读取该文件，不运行 `scripts/bilingual/` 下的脚本，也不应用任何双语布局约束。

双语任务禁止临时编写脚本直接遍历或修改幻灯片 XML；必须使用双语专项工作流规定的固定脚本。此限制不改变普通 PPT 的创建、编辑和 QA 流程。

双语编辑默认使用 PowerPoint 原生对象：源布局健康时保留或局部重排，源布局存在越界、碰撞或双语容量不足时允许重写整页布局。原中文、数据、内容图片、图表、表格、来源和备注必须保持不变；新输出 PPT 的背景可简化、重配或替换，源文件始终只读。不得在该专项路径中调用质量模式（ppt-slide）链路。

## 关键风险

| 链路 | 跳过 reference 的典型后果 |
|---|---|
| `.pptx` 从零创建 | PptxGenJS API 用错、主题对象不一致、页面类型单一、中文字号和标点不合规。 |
| `.pptx` 模板创建 | 模板页索引错误、占位符数量不匹配、文字被清空或溢出、格式属性丢失。 |
| `.pptx` 编辑 | 表格/甘特图结构错乱、group shape 坐标误判、条形与表格行不对齐、文字被截断。 |
| 网页·典雅画报风（风格 A） | 发明模板不存在的类名、主题节奏单调、图片比例错误、动效兜底资源缺失。 |
| 网页·简约商务风（风格 B） | 未遵守 S01-S22 登记版式、缺失 `data-layout`、标题居中误用、SVG 内写文字、校验失败。 |
| AI 配图 | 生图服务额度或可用性受限、图片风格不一致、在图片内生成关键文字或精确数字，导致内容不可控。 |
| 图片 PPT | 把不可编辑图片误当标准 PPT、复杂中文或数据渲染错误、未做 thumbnail QA。 |
| 澄清不足 | 输出路线、页数、受众或素材假设错误，导致返工。 |

## 注意
1. **「PPT」≠ 默认排版 `.pptx`**：本场景中用户说的「PPT」「演示文稿」可能指 **排版 `.pptx`、旧版 `.ppt`、网页 HTML、图片 PPT** 任一种交付形态，不要因用户只说「做个 PPT」「PPT 文件」「幻灯片」等就默认按排版 `.pptx` 创建；输出路线未明确时必须走澄清流程确认。
2.  **禁止凭记忆或历史偏好决策**：严禁根据对话记忆、过往会话或上下文中的历史选择（如上次做过网页 PPT、常用某风格/主题色）推断本次输出格式、路线、风格或其他配置；本次用户未明确说明的一律向用户确认，不得擅自默认。
3. **QA 布局检测**：视觉检查前必须先运行 `python scripts/detect_layout.py <pptx文件路径>`，基于 XML 坐标自动检测文字重叠/溢出/空白/字号层级问题，脚本输出作为视觉检查的必查清单。脚本依赖 `lxml` 库，缺失时 `pip install lxml`。
