# 40 分钟时间控制与救援机制（timebox）

本文件是 PPTX skill 所有交付路线的统一时间控制协议。40 分钟是强制收敛和决策点，不是无条件停工线；执行者必须使用真实时间记录起点、累计里程碑、控制点和救援上限。

## 一、启动计时

当需求已足够明确，开始读取任务文件、分析素材或编写代码时，立即记为 `T0`，并计算：

- `T_plan = T0 + 10 分钟`：内容规划目标。
- `T_build = T0 + 30 分钟`：首个可打开版本目标。
- `T_review = T0 + 40 分钟`：强制收敛与交付判断点。
- `T_rescue = T0 + 50 分钟`：仅在 40 分钟时仍无可交付版本才启用的救援上限。

必须将上述时间写入任务工作目录的 `.temp/timebox.md`。若无法写入文件，则在工作记录中明确保存。上下文压缩、任务续接、工具失败和重新读取文件均不得重置 `T0`。

## 二、累计里程碑

| 累计时间 | 必须达到的状态 |
|---|---|
| 0–10 分钟 | 完成澄清、素材读取、结构分析和页面/修改方案 |
| 10–30 分钟 | 完成生成或编辑，产出首个可打开版本 |
| 30–40 分钟 | 完成最多两轮 QA、必要修复和交付 |
| 40–50 分钟 | 仅在尚无可交付版本时进入救援阶段 |

未按时达到里程碑时，立即收缩范围，不再新增非必要内容或进行视觉精修。

## 三、强制检查点

以下时刻必须读取真实时间：

1. 内容规划完成后。
2. 开始生成、编辑、生图或批量处理前。
3. 首个可打开版本生成后。
4. 每轮渲染、视觉 QA 或修复开始前和结束后。
5. 到达 `T_review` 时。
6. 最终交付前；若进入救援阶段，还须在到达 `T_rescue` 前再次检查。

预计耗时超过 2 分钟的操作，启动前必须检查剩余时间。

## 四、正常 QA 与降级

- 正常 QA 最多两轮。一次“渲染/截图 → 检查 → 集中修复 → 重新渲染”计为一轮。
- 同类问题必须先找全局根因，再一次性批量修复，禁止逐页反复试错。
- 第二轮只验证修复结果并处理 P0 问题：文件无法打开、空白页、缺页、关键内容缺失、明显重叠或截断、图片缺失或严重变形。
- 距离 `T_review` 不足 10 分钟时，禁止新增页面、重构版式、重新翻译全稿或启动全量视觉精修，改做快速 QA。
- 非 P0 问题不阻塞阶段性草稿交付，但必须在交付说明中列出。

## 五、到达 40 分钟后的处理

到达 `T_review` 后，立即停止扩展范围和非必要精修，并执行最低可交付检查。

### 情况 A：已有可交付版本

若版本通过最低可交付检查，立即交付并结束任务。未完成精修时，必须标注为“阶段性草稿”，不得称为“最终版”。

### 情况 B：尚无可交付版本

允许自动进入一次最多 10 分钟的救援阶段，无需先等待用户回复。救援阶段只能：

- 补齐缺页或关键内容。
- 修复导致文件无法打开的问题。
- 修复明显重叠、截断、缺图或严重变形等 P0 问题。
- 打包并执行一次快速 QA。

救援阶段禁止新增非必要页面、改换视觉风格、重写完整内容、继续普通精修或启动新一轮全量 QA。一旦形成可交付版本，应立即交付，不必用满 10 分钟。

到达 `T_rescue` 后仍未形成可交付版本，停止继续制作，保存内部工作文件并汇报；继续执行需要用户明确授权新的时间或缩小范围。

## 六、最低可交付检查

只有同时满足以下条件，当前版本才可提供给用户：

1. 文件能够正常打开。
2. 计划页均已生成，不存在缺页、空白页或关键内容缺失。
3. 不存在明显文字重叠、截断、图片缺失或严重变形等 P0 问题。
4. 若尚有非 P0 问题，交付说明明确标注“阶段性草稿”并列出未完成项。

若任一条件不满足，不得把文件发送给用户；只能保存为内部工作文件并汇报。仅当用户明确表示接受当前状态时，才可交付未完成稿，且必须标注“未完成版”。

## 七、快速 QA 清单

1. 文件能否打开，是否存在空白页。
2. 是否缺页或缺少关键内容。
3. 是否有明显文字截断、溢出或重叠。
4. 图片是否缺失、严重变形或比例错误。

## 八、无法交付时的汇报模板

```markdown
【40 分钟控制点及救援阶段汇报】
✅ 已完成：<具体文件、页面和步骤>
❌ 未完成：<剩余页面、检查或修复>
⚠️ 当前版本问题：<导致暂不可交付的 P0 问题>
🔧 建议下一步：<只给一个最高优先级动作>

当前文件状态：<可交付的阶段性草稿 / 仅内部工作文件 / 尚未形成文件>
文件路径：<仅在通过最低可交付检查或用户明确接受未完成稿时提供>
如需继续，请明确授权新的可用时间或缩小范围。
```

## 九、禁止行为

- 禁止凭感觉估算时间而不读取真实时间。
- 禁止在上下文压缩或任务续接后重新计时。
- 禁止无上限地重复“修复—渲染—检查”。
- 禁止把救援阶段用于视觉精修或需求扩展。
- 禁止超过 `T_rescue` 后自动继续。
- 禁止把未完成版本称为“最终版”。
