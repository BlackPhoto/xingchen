# 修复方案：代理问题协助

> **对应场景**：TeleAgent 正常可用的前提下，用户遇到"网页/软件打不开"类网络问题，可能是代理相关（外网受限需开代理 / 代理残留 / 代理未生效 / 代理链路不可用）。
> **典型表现**：浏览器打不开境外/受限网站；Clash 等代理软件已开但网页仍打不开；代理软件已关但网页仍异常（残留）；用完代理想恢复直连。
> **重要**：本检查项**以 TeleAgent 正常可用为前提**。若 TeleAgent 整体无法使用，不进入本检查项（用户无法触发技能，应联系客服支持）。本检查项只保证"代理环境不会导致 TeleAgent 故障"，**不主动建议用户开/关代理**，仅协助用户解决外网受限访问问题。

---

## 触发条件

用户说出以下任一意图时触发：

| 触发表述 | 实际意图 |
| --- | --- |
| "网页打不开 / 网站打不开 / 打不开外网" | 先基础排除（确认是否代理问题）→ 再进入代理流程 |
| "想开代理访问外网 / 帮我打开代理" | 主流程 1：开代理（外网受限） |
| "代理关了但网页还是打不开" / "清除代理残留" | 主流程 2：清残留 |
| "用完代理怎么关" | 主流程 2：关闭 + 清理 |
| "我开了代理但好像没生效" | 附加流程 C1：代理未接管 |
| "代理开着但网页还是打不开" | 附加流程 C2：代理链路不可用 |

> **不触发**：用户询问代理原理（正常回答）；TeleAgent 整体无法启动（引导联系客服）；内网资源打不开（应查 VPN/直连/NO_PROXY，不属于"开代理"解决范围）。

---

## 检查项定位与安全边界

本检查项操作对象为**系统级**（系统代理、环境变量、代理软件进程），不落入 TeleAgent 文件红/黄/绿分级，按磁盘清理同级门禁处理。以下约束写死，Agent 不得违反：

| # | 安全约束 |
| --- | --- |
| 1 | **只读检测不需要确认**。修改类操作分级：**选代理项、启动代理需用户确认**；**补 NO_PROXY、清残留免确认**（执行时同步告知，不等回复）；回滚后直接给手动指引 |
| 2 | 启动代理**只启用"规则模式 + 系统代理"**，**不启用 TUN**、不写系统级代理环境变量（避免切断 TeleAgent） |
| 3 | 启动前**预检**环境变量代理 + NO_PROXY 完整性，有残留先提示/补全（防止重启后 Server 挂） |
| 4 | 无代理软件时**中性话术**："访问该资源需要代理，请自行准备合规代理软件"，不提供购买/下载渠道 |
| 5 | 检测到多个代理软件时**用卡片单选让用户选**（一个软件一张卡片：名称+运行状态+端口），不自动猜 |
| 6 | 基础排除发现非代理问题（断网/DNS/网关）→ **只读定位 + 指引**，不进入代理流程 |
| 7 | 目标 URL 需用户提供，否则只做网络健康检测，不做"问题是否解决"判定 |
| 8 | 存活自检失败 → **先 repair → 再自检 → 仍失败才 rollback**，回滚后必须给出手动操作指引 |

## 交互规范（卡片式选择）

> 所有需用户决策的流程，一律用 **TeleAgent 原生选项卡片** 呈现，Agent 不得降级为纯文本提问。卡片要素：
> - **标题**：一句诊断结论（如“检测到 3 个代理软件”）。
> - **每个选项**：一段文本，含选项文字 + 该选项将执行的后续动作/影响，避免误选。

### 交互分级

| 交互类型 | 适用范围 | Agent 行为 |
| --- | --- | --- |
| **卡片单选（需确认）** | ① 多代理选择（主流程1 Step3）；② 启动代理前一次性授权（主流程1 Step4） | 用卡片列选项，等用户点选后再进入后续 |
| **执行即告知（免确认）** | ① 补全 NO_PROXY（主流程1 Step2）；② 清除/关闭代理残留（主流程2 Step3） | 直接执行，但执行时用一句话说明“将执行 xxx（影响 xxx）”，不等待回复 |
| **直接指引（无选项）** | 回滚后的手动操作指引 | 直接输出操作文本，不再提供选项 |

> 免确认前提约束：**补 NO_PROXY** 只在现有值后追加 `localhost,127.0.0.1`，不删已有内容；**清残留**仅在确认为“无代理进程/端口”（残留）或用户已明确要求关闭代理时才执行，若系统代理正在被正常代理进程使用（非残留），不得静默改动，改为卡片确认。

## 诊断检查

### 检测脚本

**Windows：**
```powershell
.\scripts\check-proxy.ps1                      # 完整诊断
.\scripts\check-proxy.ps1 -HealthCheck         # 仅 TeleAgent 云端存活自检
.\scripts\check-proxy.ps1 -TargetUrl "https://目标"  # 附加目标 URL 对比
```

**macOS / Linux：**
```bash
chmod +x ./scripts/check-proxy.sh && ./scripts/check-proxy.sh
./scripts/check-proxy.sh -H                    # 存活自检
./scripts/check-proxy.sh -u "https://目标"
```

### 检测项

| 层 | 检测项 | 说明 |
| --- | --- | --- |
| 基础排除 | 网卡状态 / DNS 解析 / 公网连通 | 确认是否真的是网络问题 |
| 代理层 | 系统代理 | Windows 注册表 / macOS networksetup / Linux gsettings |
| 代理层 | 环境变量代理 + NO_PROXY 完整性 | 是否缺失 localhost/127.0.0.1 |
| 代理层 | 代理软件进程 + 安装路径 | 检测是否安装/运行 |
| 代理层 | 代理端口监听（归属验证） | 常见端口 7890/7897 等，仅当监听者是代理进程才算；非代理进程占用的端口（如 TeleAgent node 的 8080）记入 `suspect` 仅提示 |
| 代理层 | TUN 接管（归属验证） | 网卡名匹配代理软件名（mihomo/clash/verge 等）才算代理 TUN；wintun/tap/utun 等通用驱动网卡（企业 VPN、macOS 系统 utun 常用）记入 `tun_suspect` 仅提示，不告警 |
| 验证层 | TeleAgent 云端连通 | 存活自检（150.223.245.6:443） |
| 验证层 | 目标 URL 连通 | 直连 vs 真实经代理端口请求对比（`proxy_ok` 为真实测试结果，收到 HTTP 响应含 403 即链路可用） |

### 判定逻辑

| 状态 | 判定 | 对应问题 |
| --- | --- | --- |
| `normal` | 网络正常、无代理残留、云端可达 | 无需处理 |
| `warning` | NO_PROXY 缺 localhost / 系统代理残留 / TUN 激活 | 建议修复 |
| `failed` | TeleAgent 云端不可达 | 需优先定位 |

## 主流程 1：开代理（外网受限）

```
Step 1  基础排除（check-proxy）→ 确认为网络/代理问题（非断网/DNS/网关）
Step 2  前检（check-proxy）：环境变量代理 + NO_PROXY 完整性
        → 若 NO_PROXY 缺 localhost/127.0.0.1 → 执行即告知：Agent 说明“将补全 NO_PROXY（追加 localhost,127.0.0.1）”，直接 fix-proxy -Action fix-noproxy，不等用户确认
Step 3  检测代理软件（check-proxy.proxy_app）
        → 无：中性告知"需自行准备合规代理软件"，流程结束
        → 有：卡片单选（一个软件一张卡片：名称+运行状态+端口），用户点选一个后进入 Step 4
Step 4  启动代理前卡片授权（一次性授权，两个选项：①"启动并授权（若影响 TeleAgent 将自动修复，仍失败自动回滚）" ②"取消"）。用户点选后才执行 Step 5
Step 5  fix-proxy -Action assist  → 启动代理软件 + 等待端口
        判定语义：**代理端口有监听（归属验证）才算"已运行/成功"（status=started）**；
        仅后台服务/辅助进程在跑（如 clash-verge-service）而端口无监听时**不算已运行**，脚本仍会探测并启动主程序；
        端口最终无监听一律 status=failed（detail 含失败原因，"proxy app not found" → 提示用户准备合规代理软件）
Step 6  存活自检：check-proxy -HealthCheck
        ├─ 通过 → 继续测试目标 URL（check-proxy -TargetUrl）→ 汇报"代理已生效，目标可访问"
        └─ 失败 →
              ├─ fix-proxy -Action repair（尽力降级接管方式）
              │     └─ 再次 check-proxy -HealthCheck
              │           ├─ 通过 → 汇报"已修复接管方式，TeleAgent 正常"→ 继续测目标 URL
              │           └─ 仍失败 →
              │                 ├─ fix-proxy -Action rollback（恢复启动前状态）
              │                 └─ 告知"该代理模式会切断网络，已自动回滚" + 手动操作指引
              └─（repair 返回 no_action 时直接走 rollback）
```

> **关键**：存活自检失败 → **先修复 → 再自检 → 仍失败才回滚**，回滚后给手动指引。

### 回滚后的手动操作指引（Agent 按平台输出）

```
1. 打开代理软件 → 设置 → 关闭"TUN 模式"/"增强模式"
2. 使用"规则模式"并开启"系统代理"（不要用全局模式）
3. 重新打开浏览器访问目标网站
4. 若仍打不开，重启代理软件或检查订阅/节点
```

## 主流程 2：清除代理残留 / 关闭代理

```
Step 1  诊断（check-proxy）：查看系统代理状态、代理软件/端口、环境变量
Step 2  判定残留：系统代理开启但无代理进程/端口，或环境变量代理残留且 NO_PROXY 缺失
Step 3  处置（执行即告知）：确认为“已打开但无代理进程/端口（残留）”或用户已明确要求关闭代理时，Agent 直接执行，执行时说明一句“将关闭系统代理/清理残留变量，影响面为浏览器类应用”，不等用户确认；若系统代理正在被正常代理进程使用（非残留），则改为卡片确认，不得静默改动
Step 4  fix-proxy -Action cleanup  清理系统代理残留（无代理进程时置 0）
       （可选）fix-proxy -Action fix-noproxy  补全 NO_PROXY（如需保留代理环境）
Step 5  验证：check-proxy 复查 + 用户打开目标网页确认
```

## 附加流程

### C1：代理软件运行但系统代理未接管

- 现象：Clash 已开，但浏览器流量不过它，网页仍打不开。
- 处理：`check-proxy` 显示 `proxy_app.running=true` 但 `system_proxy.enabled=false` 或端口未监听。
- 修复：给出手动指引"在代理软件中开启「系统代理」，使用规则模式"。

### C2：代理开着但节点/订阅不可用

- 现象：代理进程在跑、端口在监听，但目标网站仍打不开。
- 处理：`check-proxy -TargetUrl` 显示 `proxy_ok=false`（经真实代理端口请求收不到任何 HTTP 响应）→ 定位为"代理链路不可用"。
- 若 `proxy_ok=true`（收到响应，含 403 风控码）但浏览器仍打不开 → 属节点质量/风控问题，提示用户换节点或检查订阅，非链路故障。
- 修复：提示用户检查订阅/节点是否过期，无自动修复。

## 修复后验证

| 验证项 | 方法 | 预期 |
| --- | --- | --- |
| TeleAgent 存活 | `check-proxy -HealthCheck` | `ok` |
| 目标网站可达 | `check-proxy -TargetUrl <url>` | 目标返回可达 |
| 代理状态干净 | `check-proxy` | 无残留 warning |

## 边界与限制

| 场景 | 处理方式 |
| --- | --- |
| TeleAgent 整体无法使用 | 不进入本检查项，引导联系客服 |
| 内网打不开 | 非本检查项范围，提示查 VPN/直连/NO_PROXY |
| 目标 URL 未提供 | 只做网络健康检测，不做"问题是否解决"判定 |
| 多个代理软件 | 卡片单选让用户选择，不自动猜 |
| 代理软件需登录/订阅 | 启动后端口监听成功即视为生效；订阅问题走 C2 |
| 存活自检失败且 repair 无 API | 直接回滚 + 手动指引 |
| 修改系统代理/环境变量 | 选代理、启动代理需用户确认；补 NO_PROXY、清残留免确认但执行时告知 |
| 机器级代理环境变量 | Agent 不直接改，给命令/建议 |
