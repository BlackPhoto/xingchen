# 修复方案：MCP 配置 JSONC 格式错误

> **对应场景**：用户在 TeleAgent.jsonc 上添加/删除/修改字段后，重启前主动检查格式是否正确
> **触发方式**：用户说"帮我看看改的对不对""我刚加了MCP server，检查下格式"等
> **重要**：TeleAgent.jsonc 格式错误会导致 TeleAgent 无法启动，届时无法通过本技能修复，只能手动编辑配置文件。因此修改配置后、重启前务必先运行检查。

---

## 问题定位

TeleAgent 使用 JSONC 格式的配置文件（`TeleAgent.jsonc`），JSONC 在标准 JSON 基础上允许 `//` 和 `/* */` 注释。用户手动编辑时容易引入格式错误，导致解析失败。

### 配置文件位置

> ⚠️ **TeleAgent 2.6+ 多用户结构**：配置文件位于 `users\<账号ID>\TeleAgent.jsonc`，优先用环境变量 `TELEAGENT_CONFIG_DIR` 定位当前账号配置根。

| 系统 | 标准路径 |
| --- | --- |
| 全部（2.6+） | `$TELEAGENT_CONFIG_DIR\TeleAgent.jsonc`（环境变量，最准）→ `%USERPROFILE%\.config\TeleAgent\users\<账号ID>\TeleAgent.jsonc` |
| macOS / Linux | `~/.config/TeleAgent/users/<账号ID>/TeleAgent.jsonc` |

> 若设置了 `XDG_CONFIG_HOME` 环境变量，则以该变量替代 `~/.config` 作为配置根。
> 标准路径找不到时，搜索目录下 `.jsonc`/`.json`/`.jsonc.bak` 疑似文件。

### 常见错误类型

| 类型 | 典型原因 | 示例 |
| --- | --- | --- |
| UTF-8 BOM | 编辑器保存时自动添加 BOM 头 | 文件前3字节为 `EF BB BF` |
| 控制字符 | 复制粘贴带入不可见字符 | 某行含 `0x0B` 等控制字符 |
| 全角符号 | 中文输入法未切换 | `"key"：value` → `"key":value` |
| 尾逗号 | JSON 不允许末尾逗号 | `{"a":1,}` |
| 连续逗号 | 编辑时多打逗号 | `[1,,2]` |
| 括号不匹配 | 缺少闭合或多出闭合 | `{"a":[1}` |
| 未闭合注释 | `/*` 后忘记写 `*/` | 多行注释未关闭 |
| JSON 解析失败 | 其他语法错误 | 缺少逗号、键名未加引号等 |

## 修复前安全检查

| 序号 | 安全检查项 | 确认内容 |
| --- | --- | --- |
| 1 | 已备份 | 确认待修改文件已创建 .bak 备份（由 mcp-check-jsonc 脚本自动完成） |
| 2 | 非红线区 | `TeleAgent.jsonc` 的格式修复属于黄色区，可修改但需 JSON 校验 |
| 3 | 用户知情 | 确认已向用户展示诊断结果并获得修复确认 |
| 4 | 可回滚 | 确认修复失败时可通过 .bak 备份回滚 |

---

## 修复流程

```
Step 1  运行 mcp-check-jsonc 脚本（备份 + 诊断）
Step 2  向用户展示诊断结果，等待确认
Step 3  运行 mcp-fix-jsonc 脚本（修复 + 验证 + 回滚兜底）
Step 4  告知用户重启 TeleAgent 生效
```

---

### Step 1：运行诊断脚本

**Windows：**
```powershell
.\scripts\mcp-check-jsonc.ps1
```

**macOS / Linux：**
```bash
chmod +x ./scripts/mcp-check-jsonc.sh && ./scripts/mcp-check-jsonc.sh
```

脚本执行内容：
1. 定位配置文件（macOS/Linux 优先 `XDG_CONFIG_HOME`，否则回退 `~/.config`；找不到时搜索目录下 `.jsonc`/`.json`/`.jsonc.bak` 疑似文件）
2. 自动备份 `TeleAgent.jsonc` 为 `.bak`
3. 检测编码问题：UTF-8 BOM、不可见控制字符
4. 检测全角符号混入（11种全角→半角映射）
5. 剥离 JSONC 注释（位置保持，注释替换为空格、换行保留）
6. 在剥离后内容上检测结构问题：尾逗号、连续逗号、括号不匹配、未闭合注释
7. 尝试 JSON 解析（优先 PowerShell/node/python，获取详细错误信息）
8. 输出结构化诊断结果和修复建议

---

### Step 2：向用户展示诊断结果，等待确认

Agent 输出格式：

```
MCP 配置格式诊断结果：

| 问题类型 | 数量 | 详情 |
| --- | --- | --- |
| UTF-8 BOM | 1 | 文件前3字节为 EF BB BF |
| 全角符号 | 3 | 第8行第12列：：→ : 等 |
| 尾逗号 | 2 | 第15行第5列、第23行第10列 |

建议修复方案：移除 UTF-8 BOM + 替换全角符号 + 移除尾逗号
可自动修复。是否执行修复？[确认 / 拒绝]
```

| 诊断结果 | Agent 行为 |
| --- | --- |
| 无格式问题 | 告知用户"配置格式正确，可以安全重启"，流程结束 |
| 有格式问题（用户确认） | 进入 Step 3 运行修复脚本 |
| 有格式问题（用户拒绝） | 不修改，告知用户当前配置仍存在格式问题 |

---

### Step 3：运行修复脚本

**Windows：**
```powershell
.\scripts\mcp-fix-jsonc.ps1
```

**macOS / Linux：**
```bash
chmod +x ./scripts/mcp-fix-jsonc.sh && ./scripts/mcp-fix-jsonc.sh
```

脚本执行内容：
1. 验证备份文件存在
2. 按顺序应用修复，每类修复后尝试 JSON 解析：
   - 修复 UTF-8 BOM（去除文件前3字节）
   - 清除控制字符（正则移除 0x00-0x1F 范围内除 \t \n \r 外的字符）
   - 替换全角符号（字符串感知：仅替换语法位置的全角字符，字符串值内保留）
   - **尝试解析 → 通过则结束**
   - 移除尾逗号（字符串感知：逗号后跳过空白和注释，若紧跟 } 或 ] 则移除该逗号）
   - 修复连续逗号（字符串感知：连续两个逗号合并为一个）
   - **尝试解析 → 通过则结束**
   - 补全缺少闭合的括号（在文件末尾追加缺失的 } 或 ]）
   - 修复未闭合的多行注释（在文件末尾追加 `*/`）
   - **尝试解析 → 通过则结束**
3. 所有修复用尽仍失败 → 自动从 .bak 回滚，输出错误信息

**关键特性：**
- 修复过程中保留 JSONC 注释（只修复语法错误，不丢失注释）
- 全角符号替换、尾逗号移除均为字符串感知（不修改字符串值内部内容）
- 尾逗号检测时跳过注释内容（正确处理逗号后有注释再跟 } 的场景）
- 每类修复后立即验证，尽早停止

---

### Step 4：告知用户重启

直接告诉用户：

> 修复完成，**请重启 TeleAgent 使配置生效**。重启后如果仍有问题，请再次触发本技能做二次诊断。

> Agent 不应直接执行重启命令（会杀死自身进程），只告知用户手动重启。

---

## 修复后验证

用户重启 TeleAgent 后，Agent 再次运行 `mcp-check-jsonc` 脚本进行验证：

| 验证项 | 方法 | 预期 |
| --- | --- | --- |
| JSON 格式合法 | 脚本输出 `[通过]` | 通过 |
| MCP 配置可解析 | 脚本内置校验 | 通过 |
| MCP Server 连接 | 日志中 `MCP server connected` | 已连接 |

---

## 边界与限制

| 场景 | 处理方式 |
| --- | --- |
| 字符串值内的全角符号 | 不替换（字符串感知修复保留原文） |
| 全角引号混入 | 始终替换为半角引号（JSON 语法要求） |
| 尾逗号后有行注释再跟 } | 正确识别为尾逗号并移除 |
| 缺少逗号（相邻键值对间） | 由 JSON 解析失败间接识别，脚本不单独处理此类型 |
| 配置文件无格式问题 | 输出 `[通过]`，退出 |
| 所有自动修复用尽仍失败 | 回滚到 .bak 备份，输出错误信息，建议用户手动修改 |
| 标准路径找不到配置文件 | 搜索目录下 `.jsonc`/`.json`/`.jsonc.bak` 疑似文件，仍找不到则报错退出 |
| macOS/Linux 设置了 `XDG_CONFIG_HOME` | 使用该变量替代 `~/.config` 作为配置目录 |
| 修复后注释丢失 | 注释保留在原始内容中（修复直接操作原始内容，不经过剥离-重写流程） |
